= AI Data Engine ダッシュボードでストレージの健全性を評価する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
調査対象を決定する前に、ストレージの状態を把握する必要があります。お客様の組織が定めるコールドデータおよび陳腐データの分類基準を満たすストレージ容量はどれくらいですか？また、これらのカテゴリに該当するデータが最も多く保存されているシステムや所有者は誰ですか？例えば、容量アラートに対応したストレージ管理者は、スキャンされたストレージの大部分がコールドデータであることを確認し、最も影響の大きいシステムを詳しく調べて、直ちに調査を開始できます。

NetApp Console から、*ガバナンス* > *AI Data Engine UI* を選択します。ダッシュボードはデフォルトで開きます。



[[understand-how-much-storage-is-affected]]
== 影響を受けるストレージ容量の把握

概要パネルには、スキャン対象環境全体における問題の規模が表示されます。

* *コールドデータ*：コールドデータしきい値（デフォルト：1年）以内にアクセスされていないストレージ。お客様の組織は、データ保持およびガバナンスポリシーに従って、このデータを評価することができます。
* *古いデータ*：古いデータのしきい値（デフォルト：3年）内にアクセスまたは変更されていないストレージ。組織のデータのライフサイクルポリシーに従って、アーカイブや削除などの措置を決定する前に、古いデータの見直しが必要となる場合があります。
* *公開ディレクトリ*：アクセス設定が過度に緩いディレクトリ。これらは、ストレージ消費量とは無関係なガバナンスリスクを表します。
* *データリソース*：現在スキャンされているボリューム、共有、およびバケットの数。
* *スキャンされたファイル総数*：スキャンされたすべてのデータリソースでインデックス化されたファイルの総数。


コールドおよびステールのしきい値は、設定内容を反映しており、*Configuration* > *Settings* で変更できます。デフォルト値は製品のデフォルト値であり、法的、コンプライアンス、または業界標準のデータ保持期間を表すものではありません。link:../administer/configure-settings.html["コールドデータと古いデータのしきい値を設定する"]を参照してください。

_Active versus reclaimable storage_ のグラフは、スキャンされたすべてのリソースにおける、アクティブデータとコールドデータおよび古いデータの割合を示しています。利用頻度の低いデータ、古いデータ、または重複データの割合が高い場合は、ストレージの最適化に大きな機会があることを示している可能性があります。

「システム」および「システムタイプ」フィルターは、ダッシュボードのスコープを制御します。ストレージシステムがフィルターリストに表示されない場合は、link:../data-sources/connect-data-source.html["データソースを接続する"]を参照してください。



[[identify-storage-optimization-opportunities]]
== ストレージ最適化の機会を特定する

要約パネルとグラフを使用して、ストレージ最適化の機会を特定し、優先順位を付けます。

* 総量が最も多いリソースではなく、潜在的に回収可能なサイズが最も大きいリソースに焦点を当ててください。ほとんどがコールドデータまたは古いデータで構成されている小規模なシステムは、ほとんどがアクティブな大規模システムよりも、最初に評価するリソースとして適している場合があります。
* 孤立したファイルではなく、大量のコールドデータや古いデータが集中している場所を探してください。1つのリソース上で、数十テラバイトものデータが古くなったというしきい値に達した場合は評価が必要ですが、個々のファイルについては対応が必要ない場合もあります。




[[move-from-the-dashboard-to-investigation]]
== ダッシュボードから調査画面へ移動

調査する価値のあるリソースまたは所有者を特定したら、ダッシュボード下部の表を使用して詳細情報に直接移動してください。

「再利用可能なストレージによる上位データリソース」表には、スキャンされたストレージリソースが、重複しているデータ、または組織のコールドデータおよび古くなったデータのしきい値を満たしているデータの割合に基づいてランク付けされて表示されます。いずれかの行を選択すると、そのリソースに絞り込まれた調査ビューが開きます。そこから、link:investigate-unstructured.html["非構造化"]タブを使用してコールドファイルまたは古いファイルを識別するか、link:investigate-directories.html["ディレクトリ"]タブを使用して権限の漏洩状況を監査します。

「再利用可能なストレージによる上位データ所有者」テーブルには、再利用可能な可能性のあるデータを所有しているデータ所有者が表示されます。任意の行を選択すると、link:investigate-unstructured.html["調査"]ビューがその所有者のファイルに絞り込まれた状態で開きます。そこから、結果を確認したり、それに基づいて操作したり、ポリシーとして保存したりできます。
