= AI Data Engineの構造化データを調査する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
データベースのストレージ容量が予期せず増加している場合は、テーブルのメタデータでフィルタリングして、サイズが大きすぎるテーブルや、最初に発見されてからアクティビティが全くないテーブルを特定します。例えば、ストレージ管理者は、以前のスキャン以降変更されていない大きなテーブルを特定し、データベース所有者と連携してそれらが依然として必要かどうかを評価することができます。

.開始する前に
* 少なくとも1つのデータベースデータソースが接続され、スキャンが実行されている必要があります。link:../data-sources/connect-data-source.html["データソースを接続する"]を参照してください。




[[review-the-database-table-listing]]
== データベーステーブル一覧を確認する

.手順
. AI Data Engine の UI で「調査」を選択します。
. 「構造化データ」タブを選択します。
+
この表には、データベーステーブル名、スキーマ、DBサーバー、検出時刻、テーブルの寸法（列数×行数）、およびテーブルサイズが表示されます。





[[identify-oversized-or-unused-tables]]
== 大きすぎるテーブルや使用されていないテーブルを特定する

フィルターを使用して、再利用の機会が最も期待できるテーブルのみを表示するように絞り込んでください。

.手順
. 「フィルターを追加」を選択し、次に「検出時刻」を選択します。
. 複数のスキャンサイクルにわたって存在しているテーブル（例えば、1年以上前に初めて検出されたテーブル）を表示するように範囲を設定します。
. さらに絞り込むには、再度 *フィルターを追加* を選択し、DBサーバーまたはスキーマでフィルターして、特定のシステムに焦点を当てます。
+
適用されたフィルターは、フィルターバーの下にタグとして表示されます。フィルターを追加するたびに結果が更新されます。



利用可能なフィルターの完全なリストについては、link:use-filters.html["フィルターを操作する"]を参照してください。



[[review-table-details]]
== 表の詳細を確認する

テーブルの行を選択すると詳細パネルが開き、そのテーブルが再利用の対象となるかどうかを評価できます。

詳細パネルには、DBサーバー、スキーマ、テーブルのディメンション、テーブルサイズ、および検出時刻が表示されます。この情報を使用して、テーブルが検出後に拡大したか、変化していないかを確認してください。


NOTE: データベーステーブルを操作する前に、データベース所有者と調整して、そのテーブルが不要になったことを確認してください。



[[save-findings-as-a-policy]]
== 調査結果をポリシーとして保存する

関心のあるテーブルを特定するフィルターを適用した後、継続的な監視のためにその基準を保存します。

.手順
. フィルターツールバーの「ポリシーの作成」を選択します。
. 保険申込書にご記入ください。link:../policies/create-policy.html["ポリシーを作成します。"]を参照してください。


構造化タブからフィルタリングされた結果をダウンロードするには、image:icon_download_file.png["ダウンロード"]を選択します。
