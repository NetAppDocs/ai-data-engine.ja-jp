= AI Data Engine の要件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine（AIDE）を展開する前に、環境のネットワーク、Kubernetes、サイジング、およびオペレーティングシステムの要件を確認してください。シングルノード展開の場合、Linux VMをご用意いただければ、AI Data Engineがその他のすべてを自動的にプロビジョニングします。マルチノード展開の場合、独自のKubernetesクラスタをご用意いただく必要があります。

== AIDEシングルノード展開の要件

Linux VM を用意していただくと、AI Data Engine が k3s を含むその他すべてを自動的にプロビジョニングします。Kubernetes の設定や管理は不要です。ホストの準備、ディスク容量、ファイアウォールの要件については、link:single-node-prerequisites.html["AIDEシングルノード展開の前提条件"] を参照してください。



[[vm-sizing]]
[[single-node-vm-sizes]]
=== VMサイジング

これらのサイズは、3～4日間の初期スキャン期間に最適化された推奨基本構成であり、厳密な制限ではありません。<<flexible-sizing-single-node,柔軟なサイズガイドライン>>を参照して、これらの数値を左右する要因と、それらを超えてスケールする方法をご確認ください。

[cols="1,1,1,1,1,1,1,1"]
|===
| サイズ | vCPU | RAM | ディスク | Storage IOPS | ストレージスループット | Network | おおよそのファイル 


| 小規模 | 16 | 64 GB | 500 GB | 8,000 | 1,000MB/s | 1 GbE | 200 million 


| 中 | 32 | 128 GB | 2 TB | 12,000 | 1,500MB/s | 1 GbE | 10億 


| 大規模 | 96 | 192 GB | 6 TB | 16,000 | 2,000MB/s | 10 GbE | 30億 
|===

NOTE: あらゆる規模の導入において、NVMe SSDまたはその他のソリッドステートストレージの使用を推奨します。この表のディスク値は、AIDEデータボリュームのストレージ専用です。OS、k3s ランタイム、および AIDE データがすべて単一のディスクを共有する場合は、選択したサイズのディスク値に約 65 GB を追加してください。たとえば、単一ディスク上の小規模な導入では、合計約 565 GB が必要です。


NOTE: 単一ノード構成のAIDEデータボリュームには、NFSではなくブロックストレージを使用してください。NFSをバックエンドとするストレージは、パフォーマンス低下の原因となる可能性があります。



[[flexible-sizing-guidelines]]
[[flexible-sizing-single-node]]
=== 柔軟なサイズガイドライン

<<single-node-vm-sizes,小型、中型、大型の構成>>これらは、3～4日間の初期スキャン期間における推奨される基準値であり、ソフトウェアによって強制される厳密な制限ではありません。

サイズ推奨の根拠は何ですか？::
+
--
* *ファイルとディレクトリの合計数*：カタログ化するオブジェクトの総数は、コンピューティングとストレージの要件を決定する主要因です。オブジェクト数が増えるほど、メモリ、CPU、ストレージの必要量も比例して増加します。
* *ディレクトリ構造*：リソースの使用量は、ディレクトリのネストの深さや、ファイルが共有やボリュームにどのように分散されているかによって異なります。深くネストされた構造や高度に断片化された構造は、よりフラットな階層構造で同じファイル数の場合よりも多くのリソースを必要とする可能性があります。
* *必要なスキャン処理能力*：初期カタログの完了速度は、CPUとメモリ割り当てに直接関係します。推奨サイズを下回るプロビジョニングを行うと、スループットが低下し、初期スキャンウィンドウが長くなります。
* *ストレージ パフォーマンス*：ハイパフォーマンス ストレージを強く推奨します。メタデータのインデックス作成とイベント処理には、展開規模に比例した持続的な IOPS とスループットが必要です。


--
展開したサイズが小さすぎたり、そのサイズを上回ったりした場合はどうなりますか::
+
--
各設定は、特定のファイル数とスキャン速度に合わせて調整されています。お使いの環境が構成でサポートされている範囲を超える場合、以下のことが予想されます：

* *初期カタログ期間の延長*：計算処理能力の低下により、1日あたりのスキャン対象オブジェクト数が減少します。例えば、30億個のオブジェクトを対象とするデプロイメントでも、より小さなサイズでプロビジョニングされた場合、目標の3～4日よりも大幅に時間がかかる可能性があります。
* *継続的な取り込みスループットの低下*：継続的な負荷がかかると、新しいファイルイベントと増分スキャン更新の処理速度が低下します。
* *スキャンの停止*：AI Data Engineコンポーネントは、展開する規模に合わせて構成されます。環境がそのサイズを大幅に超える場合、スキャン速度が低下するだけでなく、停止してしまう可能性があります。ワークロードの異常やリソースの制約を確認するには、link:../administer/monitor-deployment-health.html["デプロイメントの状態を監視し、問題を調査する"]を参照してください。
* *ストレージ容量リスク*：オブジェクトの総数に対してストレージ容量が不足すると、メタデータインデックスが容量のしきい値に近づく可能性があります。ストレージ拡張を計画するには、NetAppサポートにお問い合わせください。


--
推奨サイズを超える拡張::
+
--
AI Data Engineコンポーネントはデプロイする規模に合わせて構成されているため、ホストVMにvCPU、メモリ、またはストレージを追加しても、容量が自動的に増加するわけではありません。ファイル数や必要なパフォーマンスがデプロイしたサイズを超える場合は、NetAppサポートに連絡してサイズを再調整してください。


NOTE: シングルノード展開では、高可用性や水平スケールアウトはサポートされません。環境のファイル数が常に30億を超える場合、または高可用性と耐障害性が必要な場合は、代わりにlink:deploy-aide-multi-node.html["AIDEマルチノード展開"]を展開してください。

--

[[aide-multi-node-deployment-requirements]]
== AIDEマルチノード展開の要件

独自のKubernetesクラスターをご用意いただきます。このクラスターは、他のワークロードと共有することも、AI Data Engine専用にすることもできます。インストーラーは、既存のKubernetesクラスターにAI Data Engineを展開しますが、クラスターのプロビジョニングや管理は行いません。クラスター、ストレージ、およびインストーラーホストの要件については、link:multi-node-prerequisites.html["AIDEマルチノード展開の前提条件"]を参照してください。


NOTE: すべてのマルチノード構成には、NVMeまたはハイパフォーマンスSSDストレージを推奨します。

[[flexible-sizing-guidelines]]
[[flexible-sizing-multi-node]]
=== 柔軟なサイズガイドライン

<<multi-node-sizes,小型、中型、大型の構成>> は、3～4日間の初期スキャン期間における推奨ベースラインクラスタ構成であり、ソフトウェアが強制する厳密な容量上限ではありません。60億ファイルを超える環境では、NetAppでのカスタムサイジングが必要です。

サイズ推奨の根拠は何ですか？::
+
--
* *ファイルとディレクトリの合計数*：オブジェクトの合計数は、ストレージとコンピューティングの要件を決定する主要な要因です。大規模な環境では、処理負荷を分散し、パフォーマンスを維持するために、追加のクラスタノードが必要になります。
* *高可用性レプリケーション*：マルチノード展開では、デフォルトでノード間でのデータレプリケーションが有効になり、耐障害性が向上します。レプリケーションを行うと、同等のシングルノード構成と比較して、ストレージとメモリの総必要量が増加します。
* *ノード数とワークロードの分散*：処理スループットとカタログの総容量は、クラスタ内のノード数に応じてスケールします。追加ノードは、インデックス作成のワークロードとストレージ容量の両方をクラスタ全体に分散します。
* *必要なスキャン処理能力*：クラスタ全体のCPUとメモリの割り当てによって、1日のスキャン速度と初期カタログの完了速度が決まります。
* *ノードごとのストレージ性能*：各ノードには高性能ストレージを強く推奨します。クラスタ全体の容量はノード数に比例して増加します。


--
展開したサイズが小さすぎたり、そのサイズを上回ったりした場合はどうなりますか::
+
--
各設定は、特定のファイル数とスキャン速度に合わせて調整されています。お使いの環境が構成でサポートされている範囲を超える場合、以下のことが予想されます：

* *初期カタログ期間の延長*：ノード数が少ない、またはノードあたりのリソースが少ないとスループットが低下し、初期カタログ期間が比例して延長されます。
* *ピーク負荷時の処理遅延の増加*：クラスター全体のメモリ不足により、大量のデータを取り込む期間中に処理遅延が増加する可能性があります。
* *スキャンの停止*：AI Data Engineコンポーネントは、展開する規模に合わせて構成されます。環境がそのサイズを大幅に超える場合、スキャン速度が低下するだけでなく、停止してしまう可能性があります。ワークロードの異常やリソースの制約を確認するには、link:../administer/monitor-deployment-health.html["デプロイメントの状態を監視し、問題を調査する"]を参照してください。
* *ストレージ容量リスク*：対象オブジェクト数に対してクラスタストレージが不足すると、メタデータインデックスが容量しきい値に近づく可能性があります。ストレージ拡張を計画するには、NetAppサポートにお問い合わせください。


--
推奨サイズを超える拡張::
+
--
既存のマルチノードクラスタの水平スケーリングはサポートされていません。ワーカーノードや専用ストレージノードを追加しても、スキャン処理、イベント取り込み、カタログ容量が自動的に増加するわけではありません。環境が導入したサイズを超える場合、またはスキャン処理やイベント取り込みの容量を増やす必要がある場合は、変更を計画するためにNetAppサポートまたはNetAppの担当者にお問い合わせください。


NOTE: 60億ファイルを超える規模に拡張するには、ノードのサイジングのガイダンスやカスタムスケールについて、NetAppの担当者にお問い合わせください。

--




[[kerberos-and-active-directory-requirements]]
[[kerberos-ad-requirements]]
== KerberosおよびActive Directoryの要件

Kerberos認証を使用してSMB/CIFS共有をスキャンしたり、NFSユーザーIDとグループIDをActive Directory名にマッピングしたりする前に、これらの要件を確認してください。時刻同期、DNS、およびホストパッケージの要件は、Kerberosにのみ適用されます。AIDEはKerberosクライアントです：既存のKerberosキー配布センター（KDC）に対して認証を行い、Kerberosサーバーとしては動作しません。



[[time-synchronization]]
=== 時刻同期

AIDEノードとKDCのクロックの差が許容されるクロックスキューを超えると、Kerberos認証は失敗します。Active Directoryでは、デフォルトで最大5分の時間差が許容されます。

以下の点を確認してください。

* ネットワークタイムプロトコル（NTP）は、すべてのAIDEノードでアクティブになっています。
* AIDEノードは、ドメインコントローラーと同期された時刻ソースを使用します。




[[dns]]
=== DNS

以下のDNS要件を満たしてください：

* 各AIDEノードは、完全修飾ドメイン名（FQDN）でファイルサーバーとKDCを解決できます。
* ノードがActive Directory DNSサーバーを使用するように構成する場合、そのサーバーは外部名も解決する必要があります。そうでない場合、AIDEは<<outbound-internet-access,アウトバウンドインターネットアクセス>>に記載されているエンドポイントに到達できません。
* マルチノード構成でDNS設定を変更する場合は、各ノードでActive Directory DNSサーバーを唯一のネームサーバーとして構成してください。クラスターにおける名前解決では、リストされているネームサーバーの中からランダムに1つが選択されるため、Active Directoryの名前を解決できないネームサーバーがあると、断続的な障害が発生します。


DNS設定を変更するには、link:../administer/configure-kerberos-smb-single-node.html#fix-name-resolution["シングルノード展開でSMB/CIFS共有のKerberosを設定する"] または link:../administer/configure-kerberos-smb-multi-node.html#fix-name-resolution["マルチノード展開でSMB/CIFS共有のKerberosを設定する"] の「名前解決を修正する」を参照してください。



[[host-packages]]
=== ホストパッケージ

[cols="1,3"]
|===
| 導入 | 必要なパッケージ 


| シングル ノード | Kerberosクライアントツール：Ubuntu上の `krb5-user`、またはRHEL上の `krb5-workstation`。インストーラは、Kerberos認証によるSMBアクセスをサポートするために `cifs-utils`を自動的にインストールします。 


| マルチノード | 各ノードに`cifs-utils`を、キータブを作成およびテストするホストにKerberosクライアントツールとNFSクライアントをインストールする必要があります。 
|===
KerberosベースのSMB/CIFSスキャンを行う場合にのみ、すべてのAIDEノードで `cifs-utils`が必要になります。シングルノードインストーラがインストールします。マルチノード構成の場合は、各ノードにインストールします。ノードに `cifs-utils`がない場合、SMB/CIFS共有のKerberosスキャンは失敗します。

=== NFS の Active Directory 属性
